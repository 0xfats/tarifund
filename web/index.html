TariFund.Simulation — no wallet, no real funds

Crowdfunding with automatic refunds on Tari Ootle. A creator sets a goal and a deadline. Goal reached → the creator claims the vault. Goal missed → every contributor gets their money back. No custodian, no platform fee — the contract enforces it.

Ootle clock — current epoch – (on Ootle, time is counted in epochs; the deadline is an epoch number)

How it works

  1. Create — pick a persona below, name the campaign, set a goal in TARI and a deadline epoch. Campaign::new(title, goal, deadline)
  2. Contribute — anyone can contribute while the epoch is before the deadline. campaign.contribute(account, amount)
  3. Settle — after the deadline, the creator claims the vault only if the goal was reached; otherwise each contributor refunds their own contribution in full. campaign.claim() / campaign.refund(account)

This page is a walletless simulation of the TariFund Rust template (template/src/lib.rs). It runs the same rules, with the same error messages, so you can run the whole lifecycle in two minutes. The template itself is tested against the real Ootle engine — see “How this maps to the template” below. Nothing here touches the Tari network or any real funds.

Honest limits

  • Contribution amounts are public on chain, as with any Ootle vault deposit; contributor identities are account addresses.
  • The template has not been published to Esmeralda or mainnet yet and is not audited. The demo is a simulation; the on-chain path (Sapient wallet + publish) is the next step.
  • Refunds pay the account named at contribution time — in the live app that is always the contributor's own connected account.
  • There is no partial-funding payout and no milestone release by design: goal-or-refund is the whole point.
